# cold-start: 履歴なしの新しいセッションの受け入れ試験

履歴なしの新しいセッションが、AGENTS.md と参照先だけで代表業務を始め、続けられるかを試す。
採点者は作成者以外の点検者。result のテキスト(AI の最終回答の文面)と作業フォルダのファイルだけを読んで判定する。
(機械判定)は `.atlas/tests/e2e/assert.py cold-start` が見る。(採点者)の項目だけ人が見る。

準備: `python3 .atlas/tests/e2e/prep.py cold-start <写し先フォルダ> --today YYYY-MM-DD` で写し(試験用に作る作業フォルダのコピー)を作る。
比較用の `cold-start.base.json` は `<写し先フォルダ>/../cold-start.base.json` に出る。prep.py は .git を作らず、記入もしない(写すだけ)。

## 初日シナリオ
1. 写しの直後に、新しいセッションで「こんにちは」とだけ言う。
2. 合格(次の3点がすべて満たされる):
   - 「セットアップして」(/setup)を勧めている。(採点者)
   - ファイルを変更していない。作業フォルダが cold-start.base.json と一致する。(機械判定)
   - SessionStart の出力(セッション開始時に自動で出る案内)に `[注意] git がありません` と `[要記入]` がある。(機械判定)

## 再開シナリオ
1. 同じ写しで「セットアップして」と言い、setup_answers.json の回答を `--resume`(同じ会話の続きとして送る指定)で渡す。パックは「いいえ」。
2. 「しめて」と言う。
3. 新しいセッションで「前回の続き」とだけ頼む。
4. 合格(次の4点がすべて満たされる):
   - 今日の日付・業務名・STATUS の次の一手・desk の未回答数の4つを答えている。(採点者)
   - ファイルにある情報を質問していない。1つでも質問したら不合格。(採点者)
   - git log に `chore: はじめる` と `chore: 初期設定` の2つの commit がある。(機械判定)
   - SessionStart の出力があり、1,000バイト以下。(機械判定)

## 結果の記入欄
どちらのシナリオも、SessionStart の出力バイト数を記録する。モードは headless か simulated。出力バイト数は assert.py の結果に出る値。再開は最後の「前回の続き」のセッションの値を書く。
