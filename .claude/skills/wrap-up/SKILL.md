## いつ使うか
- 終える・中断するとき。
- 起動時に `[注意] 未commit`・`[棚卸し]` が出たとき。

## 手順
1. `git status --porcelain` と `git diff --stat` で変えたファイルを宣言。エラー原文が work/ にあるか見る。
2. `work/<業務>/YYYYMMDD.md` に到達点・判断と理由・未解決(判断の全文はここ)。1行目 `# <業務> YYYY-MM-DD`。STATUS.md の1行目を `次の一手: <具体的な1文>` にし、業務索引の行を直す(追記10行内)。`[棚卸し]` なら先に手順4。
3. 回答あり(伺いの回答欄)は反映し `mkdir -p` 後 `git mv` で `work/<業務>/archive/`へ移す。承認の伺いは Q1 が はい か いいえ のときだけ移し、他は残し `ひとこと:` を TODAY に載せる(人間操作の伺いは、実行した旨が `ひとこと:` に書かれるまで残す)。再実行確認の伺いが はい なら AGENTS.md 7節の該当行の `(未検証)` を外す。新判断は伺いに。desk/TODAY.md を同じ見出しで作り直す(判断待ちは残った伺いのみ。お知らせは有効な行を残し、`AI が決めたこと: <内容>` を3行まで足す)。
4. `[棚卸し]` は(AGENTS.md の行数を除き)伺いを置かず片付け、TODAY のお知らせに `棚卸し: <したこと>` を1行。STATUS は `work/status-archive-YYYY-MM.md` へ写し、1行目・業務索引・末尾の1行だけ残す。今の業務の作業フォルダの件数超過は、STATUS・直近の日付メモ・desk/ の伺いから参照されないファイル(日付メモは除く)を `work/<業務>/archive/` へ移し、一覧を日付メモに書く。未回答・期限切れの伺いは動かさない。AGENTS.md の行数は、まとめる案を伺いに。
5. 変えたファイルに個人情報・口座番号・パスワード・原本の写しが無いか見る(AGENTS.md 中核則3)。あれば保存場所のみ。`git add -A`、次に `sh .claude/hooks/secret-guard.sh --staged`。exit 2 なら報告して止まる。無ければ `docs: <業務> <到達点>` で commit。
6. 3行で報告: 到達点/次の一手/desk の未回答数。同じ手順・注意が2回なら /skill-create を勧める。

## 止まる線
- push しない。個人情報を commit しない。
- amend・rebase・reset で履歴を書き換えない。
- ファイルを削除しない(移動は回答ありの伺いと、手順4の archive/ 行きだけ)。
- 伺いの回答・過去の日付メモ・archive/ の既存ファイルは書き換えない。

## 出力
commit 1つ。`git status --porcelain` が空で、STATUS の1行目が `次の一手: ` で始まる。回答 はい の伺いがあれば7節の `(未検証)` が外れている。
失敗時: 該当番号に1行足す
