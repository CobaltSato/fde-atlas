## いつ使うか
- 終える・中断するとき。
- 起動時に `[注意] 未commit`・`[棚卸し]` が出たとき。

## 手順
1. `git status --porcelain` と `git diff --stat` で変えたファイルを宣言。エラー原文が work/ にあるか見る。コマンドは1回に1つ(`&&` `;` `|` でつながない)。
2. `work/<業務>/YYYYMMDD.md` に到達点・判断と理由・未解決(判断はここだけ)。1行目 `# <業務> YYYY-MM-DD`。STATUS.md の1行目を `次の一手: <具体的な1文>` にし、業務索引の行を直す(追記10行内)。`[棚卸し]` なら先に手順3。
3. 回答あり(票の回答欄)は反映し `mkdir -p` 後 `git mv` で `work/<業務>/archive/`へ移す。承認の票は Q1 が はい か いいえ のときだけ移し、他は残し `ひとこと:` を TODAY に載せる(人間操作の票は実行済みまで残す)。再実行確認の票が はい なら AGENTS.md 7節の該当行の `(未検証)` を外す。新判断は票に。desk/TODAY.md を同じ見出しで作り直す(判断待ちは残票のみ)。`[棚卸し]` なら `work/STATUS.md` を `work/status-archive-YYYY-MM.md` へ写し、1行目・業務索引・末尾の1行だけ残す。票を新規に1枚だけ `desk/YYYYMMDD-棚卸し.md`(2行目 `種別: 確認`)。本文に STATUS.md・退避先・移す候補を書く。移すのは回答後。
4. 変えたファイルに個人情報・口座番号・パスワード・原本の写しが無いか見る(AGENTS.md 中核則3)。あれば保存場所のみ。`git add -A`、次に `sh .claude/hooks/secret-guard.sh --staged`。exit 2 なら報告して止まる。無ければ `docs: <業務> <到達点>` で commit。
5. 3行で報告: 到達点/次の一手/desk の未回答数。同じ手順・注意が2回なら /skill-create を勧める。

## 止まる線
- push しない。個人情報を commit しない。
- amend・rebase・reset で履歴を書き換えない。
- ファイルを削除しない(移動は回答ありの票だけ)。
- 票の回答・過去の日付メモ・archive/ の既存ファイルは書き換えない。

## 出力
commit 1つ。`git status --porcelain` が空で、STATUS の1行目が `次の一手: ` で始まる。回答 はい の票があれば7節の `(未検証)` が外れている。
失敗時: 該当番号に1行足す
