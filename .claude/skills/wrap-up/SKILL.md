## いつ使うか
- 終える・中断するとき(未完了でも)。「しめて」「終わり」「今日はここまで」「セーブして」。
- 起動時に `[注意] 未commit` か `[棚卸し]` が出たとき。

## 手順
1. `git status --porcelain` と `git diff --stat` で変えたファイルを宣言。エラーがあれば原文が work/ にあるか確かめる。
2. `work/<業務>/YYYYMMDD.md` に到達点・判断と理由・未解決を書く(判断の記録はここだけ)。1行目 `# <業務> YYYY-MM-DD`。work/STATUS.md の1行目を `次の一手: <具体的な1文>` にし、業務索引の行を直す(追記10行・800字以内)。STATUS.md の `[棚卸し]` なら先に手順3の退避。
3. 回答あり(票の回答欄)の票は反映し `mkdir -p` 後 `git mv` で `work/<業務>/archive/`へ移す。再実行確認の票が はい なら AGENTS.md 7節の該当行から `(未検証)` を外す。新たな判断は票に。人間操作の承認票は `ひとこと:` に実行済みとあるまで残す(期限付き)。desk/TODAY.md を同じ見出しで作り直す(判断待ちは残票のみ)。`[棚卸し]` なら `work/STATUS.md` を `work/status-archive-YYYY-MM.md` へ写して(消さない)、1行目・業務索引・末尾の1行だけ残す。提案は票(種別: 確認)1枚。票に退避先と、移す候補(各業務の最新以外の日付メモ・直近の日付メモから参照されないファイル)を列挙。移すのは回答の後。
4. `git add -A` 後 `sh .claude/hooks/secret-guard.sh --staged`。exit 2 なら commit せずファイルと行番号を報告し止まる。無ければ `docs: <業務> <到達点>` で commit。
5. 3行で報告: 到達点/次の一手/desk の未回答数。今回同じ手順・注意が2回あれば1行 /skill-create を勧める(無ければ出さない)。

## 止まる線
- push しない。
- amend・rebase・reset で履歴を書き換えない。
- ファイルを削除しない(移動は回答ありの票の分だけ)。
- 票の回答・過去の日付メモ・archive/ の既存ファイルは書き換えない。

## 出力
commit 1つ。`git status --porcelain` が空で、STATUS の1行目が `次の一手: ` で始まる。回答 はい の票があれば 7節の該当行の `(未検証)` が外れている。
失敗時: この手順の該当番号に1行足す
