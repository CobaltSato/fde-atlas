# /kabeuchi — 壁打ち(言語化の相棒)

## いつ使うか
- 依頼や業務がまだ言語化できていないとき(作業地図の6項目が埋まっていない)
- アイデア・モヤモヤを広げて整理したいとき
根拠: fde-guide.md §10.1(grill-me)・§2(作業地図6項目)・§14.8(質問形式)。

## 入力
- 荒いテーマ1行以上。関連資料のパス(あれば)

## 手順
1. モードを判定して宣言する: (a)アイデア壁打ち (b)業務の言語化 (c)論点整理。迷ったら相手に選んでもらう。
2. テーマを1〜3行で復唱し、認識ズレがないか確認する。
3. **(a)(c)では発散を許す**: 相手の考えを広げる問い・別視点・具体例を返す。構造化を急がず、枠に押し込まない。収束は終盤に「そろそろ整理しますか」と提案してから。
4. **(b)では作業地図6項目**(目的・完了条件/入力/SoR/Context/役割と停止線/残すもの)の空欄マトリクスを提示し、埋まっている項目と欠けている項目を宣言する。
5. 質問は1ラウンド最大5問、templates/shitsumon.md の形式(ブロック/非ブロック区分、Yes/Noか選択式優先)。**質問ラウンドは3回まで**(§10.4: 質問攻めは相手の負荷に返る)。
6. 回答を反映する。答えの無い欄は「未確定」と書く(推測で埋めない §2)。3ラウンドで埋まらない欄は「人間の宿題」として明記する。
7. (b)では §2.4 のゲートを判定する: SoRが曖昧/強い権限(書込・削除・支払)が中心/失敗時に戻せない/承認の線が引けない — 1つでもYesなら「最初にAIへ任せる業務として不向き」と伝え、§2.4の選びやすい業務例から代替を提案する。
8. 収束させて保存する:
   - (b) 作業地図を templates/sagyou-chizu.md の形式で `work/<業務名>/map.md` へ
   - (a)(c) 論点整理メモ(結論候補・論点の構造・次に考えること)を work/ へ短く。論点の関係は Mermaid(mindmap か flowchart)で図解してよい
9. 次の一手を提案する: AGENTS.md の現在地表から、どのスキル(/chousa /shorui /sekkeisho など)で実行に入るかを1つ挙げる。

## ゲート(Yes/Noで自己確認)
- [ ] (b)の場合、6項目すべてに記入または「未確定」が入ったか
- [ ] 停止線に具体的な操作名が1つ以上書かれたか(「リスクに注意」のような曖昧表現は不可)
- [ ] 質問は3ラウンド以内だったか

## 停止線(MUST NOT)
- 業務の実行(書類処理・登録・送信)には入らない。言語化とファイル1つの作成まで
- 相手の結論を勝手に確定しない(選択肢と推奨を出し、決めるのは人間)

## 出力形式
`work/<業務名>/map.md`(作業地図)または work/ 配下の論点整理メモ1ファイル。冒頭に日付(YYYY-MM-DD)とモードを書く。

## 完了条件
出力ファイルが保存され、「人間の宿題」(残った未確定)と「次の一手」が明示されている。

## 失敗時の更新先
質問がループした・枠に押し込みすぎた等の失敗は、本ファイルの「手順」該当番号へ1行注記を追記する。
