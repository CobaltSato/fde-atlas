# /wrap-up — 終了手順

## いつ使うか
セッションを終える・中断するとき。作業が完了していなくても使う(中断も終了手順で閉じる)。
根拠: fde-guide.md §5.4(終了時に残す5点)・§8(セーブポイント)。

## 入力
- 今回のセッションで扱った業務名(不明なら手順1で特定する)

## 手順
1. `git status --porcelain` と `git diff --stat` で、今回変えたファイルを列挙して宣言する。
2. `work/<業務名>/` のログへ追記する: 到達点(何が終わり何が検証済みか)・判断理由(1〜3行)・未解決論点(承認待ち・確認待ちを明示)。
3. `work/STATUS.md` を更新する。**1行目=「次セッションの最初の一手」**を具体的な1文で書く。業務索引の該当行(次アクション・最終更新)も更新する。
   - **追記は10行・800字以内**。詳細は `work/<業務名>/` の日付メモへ書き、STATUSには要点と参照だけ残す。
   - STATUS.md が 8KB を超えていたら(SessionStartの警告が出ていたら)、全文を `work/status-archive-YYYY-MM.md` へ退避(削除しない)してから、現役の業務だけで書き直す。
4. 「人間の手作業待ち」セクションを見直す: 完了した項目にチェックを付け、このセッションで発生した承認待ち・人間の手作業(承認線・フックが止めた作業を含む)をチェックボックスで追加する。長く放置されている項目は締めの報告で言及する。
5. このセッションで判断(選択・却下・例外)をしたなら、`context/decisions.md` へ1行追記する: `日時 | 対象 | 判断 | 根拠 | 承認者(または AI自動・L1)`。無ければ飛ばす。
6. `work/log.md` へ計測1行を追記する: `YYYY-MM-DD | 業務名 | 成果物 | 差し戻し有無 | 停止線で止まった回数`。
7. 道具化の提案: このセッションで**2回以上繰り返した手順・次回も使う手順**があれば、/skill-create での道具化を1行で提案する(提案のみ。実行は人間の指示後)。無ければ飛ばす。
8. 不要になった一時ファイルがあれば一覧で**提案だけ**する(削除は人間の承認後)。
9. 機密チェック: 次にYesがあれば該当行を修正してから進む —
   - credential・鍵・口座番号・個人情報をファイルに書いた自覚があるか?
   - `git status` に .gitignore 対象(.env/*.key等)が staged で出ていないか?
10. commit する。メッセージは conventional 形式で `docs:`/`chore:` + 業務名 + 到達点(例: `docs: 請求書照合 6月分の差異メモまで`)。
11. 3行以内で締めの報告をする: 到達点 / 次アクション / 未解決の数。

## ゲート(Yes/Noで自己確認)
- [ ] STATUS.md の1行目は「次の一手」になっているか
- [ ] STATUS.md への追記は10行・800字以内に収まっているか(詳細は日付メモへ逃がしたか)
- [ ] 「人間の手作業待ち」を見直したか(止められた作業が追跡されずに消えていないか)
- [ ] `git status --porcelain` が空になったか(未commitの取り残しなし)
- [ ] エラーが起きていた場合、原文を work/ に残したか(§9.6)

## 停止線(MUST NOT)
- push しない(共有は人間の指示があるときだけ)
- 履歴改変(rebase・reset --hard・amend済みcommitの上書き)をしない
- ファイル削除を承認なしに実行しない

## 出力形式
締めの報告3行(到達点/次アクション/未解決)。長い完了報告が必要な業務では templates/completion-report.md を使う。

## 完了条件
commit が作られ、`git status --porcelain` が空で、STATUS.md の1行目が次アクションになっている。

## 失敗時の更新先
commit 失敗・機密検知などこのスキル自身の失敗パターンは、本ファイルの「ゲート」へ1行追記する。
