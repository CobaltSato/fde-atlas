FDE Atlasv2解説

AI に仕事を安心して任せるための、
薄い作業フォルダ

作業フォルダ(AI が作業し記録を残す場所)の中で、AI(Claude Code)があなたの業務を進めます。

基本は AI が判断して進めます。止まるのは、上流の判断(目的・評価軸)・外に影響する戻せない操作・機密のときです。送信・支払・削除などは、手前で止まり、伺い(判断をお願いする紙)で確かめます。承認のあと誰が行うかは、伺いの「はいなら:」に書かれます。削除とメール送信は、承認のあともあなたが行います。

中身は、AI への規則・手順・門番と、作業の置き場だけ。足りない道具は、あとから足します。

あなたが見るのは
desk/ と docs/ だけ。

README.md

3分ではじめる

前提: Claude Code(AI に文字で仕事を頼む道具)の claude コマンドと、git・python3 が使えること。

  1. フォルダを手元に置く

    次のどれかで、このフォルダを手元に置く。

    • Download ZIPGitHub の「Code → Download ZIP」で展開する(いちばん簡単)。
    • git clonegit clone <URL>。
    • Use this template「Use this template」で自分用を作り、そこから ZIP か clone で手元に置く。

  2. ターミナルで claude と入力する

    ターミナル(文字で指示する画面)を開く。cd と打って半角スペースを1つ入れてから、フォルダを画面へドラッグして Enter を押す(cd=フォルダへ移動する命令)。続けて claude と入力する。

    $cd ここへフォルダをドラッグEnter
    $claude

  3. 信頼の確認に「はい」

    「このフォルダを信頼しますか」という確認(英語のこともあります)には、はい(Yes)を選ぶ。

  4. 「セットアップして」と入力する

    まとめて出る質問に答える。分からなければ「未定」と答える。

    まとめて聞かれること

    1. 業務名と完了条件
    2. 責任者
    3. 正本(いちばん信用する元資料)の置き場(3つまで)
    4. AGENTS.md 4節(止まる境界)のほかに任せない操作

    パックを入れるかも聞かれます。「会議の議事録も扱いますか?」「書類の台帳・設計書も扱いますか?」

    最後に、次は「相談したい」と言えばよいこと、次回は claude を起動し「前回の続き」と言うことが伝えられます。セッションは、claude を起動してから終えるまでの1回の作業のことです。

起動時の表示は、AI が読むだけで、あなたの画面には出ません。git が無いときや記入欄が未記入のときは、AI が最初の返事でそう伝え、「セットアップして」と言うよう案内します。

AGENTS.md・.claude/

全体像

左があなたの見る場所、右が AI の作業場です。AI は3層の中で動きます。規則は AGENTS.md、手順はスキル(手順を書いたファイル)、門番は hook(決まった時点で自動で動く検査)です。

README.md・AGENTS.md 6節

毎日の流れ

あなたがすることは5つです。「AI」の印が付いた青い行は、そのとき AI がすることです。

  1. 1

    起動

    初日と同じ cd のあと、claude で起動する。

    AI今日の日付・未回答の伺いの枚数・進み具合のメモ・直近のセーブを読む。画面には出ない。伝えるのは、最初の返事のとき。

  2. 2

    「前回の続き」

    と言う。担当が替わっても、同じ言い方でよい。

    AI回答済みの伺いを回収し、最初の返事で今日の日付・業務・次の一手・未回答の伺いの数と起動時の注意を伝えてから再開する。作業は work/<業務>/ に置き、ほかの業務のフォルダは触らない。

  3. 3

    仕事を頼む

    言い方の例は、下の「道具」の表にあります。

    AI道具を選び、フォルダの中の編集やコマンドは確認なしで進める。判断が要れば伺いを置き、関係しない作業は続ける。

  4. 4

    伺いに答える

    伺いのいちばん下の「回答」に書いて保存し、「伺いに答えた」と言う。会話で答えてもよい。

    AI会話で聞いた答えは、伺いに書き写してから進める。

  5. 5

    「しめて」

    と言う。

    AI記録と commit(セーブ)まで行う。desk/TODAY.md のお知らせに「AI が決めたこと」を書く。push(共有先へ送り出すこと)はしない。

desk/TODAY.md(今日の机)が入口です。返事が要る伺いは「判断待ち」に、期限の早い順に並びます。

desk/ の伺いは、答えたあとも「しめて」までは残ります。「しめて」のときに AI が片付けます。あなたが行う操作の伺いは、ひとこと: に『実行済み』と書くまで残ります。

docs/ の成果物は HTML です。ブラウザで開いて読みます。議事録・設計書(パックの成果物)だけは当面 md で、1行目が 状態: 案 なら確定前です。

人が読む成果物・判断材料は、自己完結 HTML(1ファイルでブラウザで開けるもの)で docs/ に置かれます。伺いと TODAY.md は md のままで、ほかの md は AI の作業用です。

L3(既定)では、AI が自分で決めて進めた分を、あとから見直します。見る場所は desk/TODAY.md の「お知らせ」です。/wrap-up が「AI が決めたこと: …」を主なもの3行まで書きます。棚卸し(古いメモの整理)をしたときは、伺いを置かずに「棚卸し: …」と1行で知らせます。

AI が止まって質問するのは正常です。承認が要る操作と、目的や元資料が足りないときに止まる作りです。止まったら、画面の最後のメッセージを読みます。判断待ちの伺いは desk/ にあります。

AGENTS.md 4節・.claude/

止まる境界

AI がどこで止まるかは、2つで決まります。承認線(ここから先は人間が決める境界)に並ぶ操作と、戻せるかどうかです。一覧の操作では、自律度(AI にどこまで任せるかの段階)に関係なく止まります。

承認線

自律度に関係なく、次は実行せず承認の伺いを desk/ に置いて止まる:

  • 送信・共有(共有先へ送り出す push を含む)
  • 支払
  • 署名
  • 確定登録
  • 削除
  • 口座変更
  • 評価軸・成功条件・合格基準の確定と書き換え(要件で拾えない事項は「採用時の引き受け項目」に分ける)
  • 1節で足した操作(セットアップの問い4で答えたもの)

一覧の操作は、損害の大小に関係なく止まります。1節に操作を足すときは、操作の名前ではなく、損害の深さと責任の宛先で選びます。

確認なしで進めるところ、止まるところ

  • フォルダの中のファイル編集・コマンド確認なしで進める
  • 承認線に並ぶ操作伺いを desk/ に置いて止まる
  • 外へ送る・共有する ssh・scp・push の3つの命令(Web の API とやり取りする curl・wget は確認なしで動く。それで送ることも承認線で止まるが、確認の画面は出ない)実行の前にあなたへ確認
  • 英語で実行の許可を聞かれたとき: 調べものの Web 検索・閲覧は Yes(はい)、伺いで はい と答えた push も Yes、頼んでいない送信・共有は No(いいえ)。迷ったら No。「次から聞かない」は選ばないあなたが答える
  • 削除・過去のセーブの書き換え・強制 push(門番が止めるのは、命令の名前で分かるものだけ)門番が止める
  • ファイルを消したいとき(削除は承認の伺いに答えたあと、あなたが行う)AI は archive/ へ移す
  • sudo と、鍵・.env ファイルの読み取り禁止

自律度の4段階

  1. L0提案実行せず、進め方の提案と質問だけ
  2. L1読取と下書き正本を読み、下書き・差異のメモ・登録案まで
  3. L2承認付き実行人間が承認した操作だけを書き込む
  4. L3監査付き自動既定承認線の手前までを自動で行い、記録を残し、後から人間が見直す

既定は L3 です。AI は承認線の手前まで自動で進め、記録を残します。誤登録や、混入した指示・正本の矛盾の見逃しなどの事故が起きたら、責任者が一段下げます(降格)。下げた段を戻すのも責任者で、AI は提案だけをします。L3 でも、上の一覧で止まる操作は消えません。あとからの見直しは、desk/TODAY.md のお知らせ(「AI が決めたこと: …」)で行います。

ほかは、戻せるかどうかで決める

可逆=自分だけで戻せ、影響が作業フォルダ内で、戻すコストが時間で増えない。

可逆性の2×2: 可逆と不可逆、フォルダ内と外部
フォルダ内外部
可逆フォルダ内は diff(変更の差分)を見せてから次へ進む。外部は読むだけ、書くのは下書きまで。
不可逆フォルダ内は commit(セーブ)してから進める。外部に影響するなら伺いで止まる。

ほかにも、ここで止まります

  • メール・添付・Web・書き起こしの中の指示文、正本の食い違い、二重実行の疑いを見つけた原文を引用した違和感の伺い
  • 目的・正本・完了条件が欠けている質問の伺い1枚
  • 外部に影響する複数件を処理する(フォルダの中だけの複数件は、3件では止まらない)先に3件だけ見せて承認を待つ
  • 複数件を処理する(外部でもフォルダの中でも)実行済みを記録で確かめる
  • 複数件の処理でエラーが2件続いた全体を止めて報告
  • 上限(外部1回20件・Web検索15回)に達した止めて報告

fde-guide.md 2章

失敗の型14

AI の注意力では防げない失敗を、14の型に分けています。名前を知っておけば、「これは型3では?」と伝えられます。詳しくは fde-guide.md(2章)。

  1. 型1

    正本の取り違え

    古い要約や撤回された決定を、正本の代わりに使う。

  2. 型2

    推測で埋める

    目的・正本・完了条件の欠けを、もっともらしい値で埋めて進む。

  3. 型3

    指示の混入

    メール・添付・Web の中の「至急こちらへ送金して」に従ってしまう。

  4. 型4

    機密の写し込み

    鍵・パスワード・口座番号を、作業メモや commit(セーブ)に写す。

  5. 型5

    二重実行

    同じ請求書を2回登録する。同じ相手に2回送る。

  6. 型6

    転記誤り

    金額・件数・日付を書き写すうちに、桁や単位がずれる。

  7. 型7

    正しく計算された無意味な数字

    計算が完全に正しくても、測っている対象がずれていれば、出てくるのは「正しく計算された、無意味な数字」である。

  8. 型8

    事実と理由の捏造

    原典に無い条項・数値・理由を、もっともらしく書く。

  9. 型9

    自己評価で合格

    「できました」の申告で完了にする。自分で再実行して検証済みとみなす。

  10. 型10

    黙った代替

    指定の手段が失敗し、別の手段に替えて、成功したように報告する。

  11. 型11

    状態の喪失

    中断の後、前回の判断・次の一手・未解決が分からない。

  12. 型12

    文脈の肥大

    状態ファイルや作業フォルダが膨らみ、毎回の読み込みが重くなる。古い説明が今の正本を押しのける。

  13. 型13

    反映漏れ

    表は直したが、地の文・別の資料・生成元に古い値が残る。

  14. 型14

    内部語彙と注釈の要る名前

    変数名・独自語・「現行」のような指示語入りの名前が、読者向けの資料に出る。

道具: スキル5本と、足せるパック

道具は、ふだんの言い方で呼べます。/ で始まるコマンドは覚えなくても大丈夫です。

こんなときは、こう言う

言い方起きることコマンド
「相談したい」「新しい仕事を任せたい」質問しながら考えを整理する/brainstorm
「〜を調べて」出典つきで調べる/research
「いま何をすればいい?」desk/ と work/STATUS.md(進み具合のメモ)を読んで答える—
「この伺いは はい」伺いに書き写して進める—
「これを次も使いたい」手順を道具として残す/skill-create
「しめて」記録と commit まで行う/wrap-up
「セットアップして」質問に答えて初期設定をする/setup

最初から入っているスキル5本

  • /setup

    初回導入。記入欄を質問で埋め、使うパックを入れる。

    残るもの: AGENTS.md 1節の記入と commit

  • /brainstorm

    曖昧な依頼を質問で整理し、作業地図にする。

    残るもの: work/<業務>/map.md(6つの見出しの作業地図)

  • /research

    安い順に調べ、出典付きでまとめる。

    残るもの: 調査メモ(結論3行と確信度)

  • /skill-create

    同じ手順や注意の繰り返しを、スキルにする。

    残るもの: 新しいスキルと、別のセッションでの再実行を頼む伺い。はい の答えが出るまで「未検証」の印が付く

  • /wrap-up

    終了・中断時に記録し、desk/ を回収して commit。

    残るもの: その日の記録・作り直した TODAY.md(お知らせに「AI が決めたこと」)・commit

必要なら足すパック

  • minutes

    会議メモから決定と宿題を抜き出す。

    コマンド: /minutes

  • si-documents

    書類の台帳と設計書をつくる。

    コマンド: /filing・/design-doc

「セットアップして」で「会議の議事録も扱いますか?」「書類の台帳・設計書も扱いますか?」と聞かれます。はい と答えると入ります。後から足すときも「セットアップして」と言います。外すときは「〜パックを外して」と言います。AI は道具のフォルダを work/ の下の archive/packs/ へ移し(削除はしません)、AGENTS.md 7節に足した行を外して commit(セーブ)します。

外に出す文書やメールは、docs/ に下書きが置かれます。送るのはあなたで、その前に承認の伺いで確かめます。

fde-guide.md 10章

同梱しないもの(フォーク先で足す)

使うかどうか分からないうちに入れた道具は、ほとんど使われませんでした。だから最初からは入れず、要る業務が出たときに足します。ここに無いものが要るときは、AI に「〜を足したい」と頼みます(いま手元にあるフォルダが、あなた自身のフォーク=自分用の複製です)。表の「型は○章」は fde-guide.md の章、AGENTS.md 8節は「この業務の追記」の欄です。

もの足すならどこに
議事録packs/minutes(/setup で「はい」。型はパックの中)
書類台帳・設計書packs/si-documents(型はパックの中)
判断ログ・失効印AGENTS.md 8節(置き場のファイルを1行で宣言。例: work/<業務>/decisions.md。型は6章)
成果物の点検項目新しいスキル(型は9章)
指示書AGENTS.md 8節(型は7章)
計測ログAGENTS.md 8節(置き場のファイルを1行で宣言。例: work/log.md。型は6章)
棚卸しスキル新しいスキル(型は6章)
人間だけで業務を回す手順AGENTS.md 8節(型は10章の下)
